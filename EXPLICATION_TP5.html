TP5 - Deploiement

Creer et deployer un modele AutoML

Du registre a l'API : decider sur la qualite, la latence, la taille et l'explicabilite.

Le but : un modele n'a de valeur qu'EN SERVICE

On fait parcourir au modele AutoML toute la chaine du TP2 : registre, alias, service HTTP, client externe, latence. Puis on decide sur quatre axes, pas seulement le F1 : qualite, latence, taille, explicabilite.

Le code, fichier par fichier

Ouvre le projet dans VS Code : chaque script commence par le meme resume (ROLE / ENTREE / SORTIE / A RETENIR). Lis-les dans cet ordre, c'est l'ordre d'execution.

reports/tp5_comparaison.md -> le tableau 4 axes + la decision

1. donnees.py

Role : Fabrique le jeu de 5000 transactions bancaires (synthetiques) avec une graine fixe.

Entree : rien (tirage aleatoire avec la graine 7)

Sortie : data/transactions.csv (5000 lignes, 568 fraudes)

A retenir : Meme graine = memes donnees pour toute la promo : c'est la base de la reproductibilite.

2. src/automl_deploy.py

Role : FLAML 90 s, extrait le modele gagnant (xgboost), verifie qu'il donne le meme F1, et l'enregistre dans le registre.

Entree : data/transactions.csv

Sortie : models/model_automl.pkl + modele 'fraude-automl' version 1 dans MLflow

A retenir : automl.model.estimator = le vrai modele, sans la machinerie de recherche : plus leger et portable.

3. src/modele_manuel.py

Role : Re-entraine le modele manuel du TP2 (foret 500/16) et l'enregistre dans le MEME registre.

Entree : data/transactions.csv

Sortie : models/model_manuel.pkl + modele 'fraude-manuel' version 1

A retenir : Pour comparer honnetement, les deux modeles suivent exactement le meme chemin.

4. src/promouvoir.py

Role : Donne l'alias 'production' a la version la plus recente d'un modele.

Entree : nom du modele en argument (fraude-automl ou fraude-manuel)

Sortie : alias production dans le registre

A retenir : Le service HTTP sert 'models:/nom@production' : il suit l'alias.

5. src/client.py

Role : Joue le role d'une application cliente : appelle l'API, puis mesure 200 appels (mediane et p95).

Entree : numero de port du service (8100 AutoML, 8101 manuel)

Sortie : affichage : reponse + latence mediane et p95 en ms

A retenir : Le p95 (95 % des appels plus rapides) montre la stabilite ressentie par les utilisateurs.

DecisionAutoML en production : F1 quasi egal, 3x plus rapide, 46x plus leger. Le manuel reste dans le registre comme version de repli : un deplacement d'alias suffit.

Ce qu'il faut retenir

  • Extraire le modele sous-jacent (automl.model.estimator) : plus leger, portable ; verifier qu'il donne EXACTEMENT le meme F1.
  • Comparer honnetement : les deux modeles suivent le meme chemin (meme split, meme registre, meme service).
  • Le F1 n'est qu'un axe : latence (surtout p95), taille (Docker, mobile), explicabilite, cout, securite du format.
  • Mediane ET p95 : le p95 montre la stabilite ; c'est lui que ressentent les utilisateurs.
  • La signature protege le service : requete incomplete -> erreur explicite SCHEMA_ENFORCEMENT_FAILED.
  • pickle/cloudpickle execute du code au chargement : acceptable seulement si la source est de confiance.
  • Reversibilite : toujours garder une copie exportable du modele hors de la plateforme.

Pieges

--env-manager localLe service utilise le Python actif : il doit contenir xgboost/lightgbm (installe avec flaml[automl]).
Port 5000 occupeUn serveur MLflow d'un autre TP tourne encore : Ctrl+C dans son terminal.
Cloud (bloc G)Endpoint facture meme sans requete : undeploy + delete le jour meme.

Commandes a connaitre

python src/automl_deploy.py ; python src/modele_manuel.py
python src/promouvoir.py fraude-automl ; python src/promouvoir.py fraude-manuel
$env:MLFLOW_TRACKING_URI = "http://127.0.0.1:5000"
mlflow models serve -m "models:/fraude-automl@production" -p 8100 --env-manager local
python src/client.py 8100 ; python src/client.py 8101
